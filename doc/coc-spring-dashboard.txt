                   COC-SPRING-DASHBOARD REFERENCE MANUAL


Spring Boot apps, beans, endpoints and memory          *coc-spring-dashboard*

                                      Type |gO| to see the table of contents.

==============================================================================
INTRODUCTION                                     *coc-spring-dashboard-intro*

coc-spring-dashboard shows the Spring Boot apps of the workspace in tree
views:

- The apps, running or stopped. |coc-spring-dashboard-apps|
- The beans of each app. |coc-spring-dashboard-beans|
- The endpoint mappings of each app. |coc-spring-dashboard-mappings|
- The properties of each running app. |coc-spring-dashboard-properties|
- The memory of each running app as sparklines.
  |coc-spring-dashboard-memory|

It also puts signs on bean definitions and request mappings in Java buffers
|coc-spring-dashboard-signs| and connects remote apps
|coc-spring-dashboard-remote|.

Installation, requirements, setup and settings are in the README of the
extension.

coc-spring-dashboard defines no key mappings. You use it through
`:CocCommand`, the tree windows and their actions menu.

==============================================================================
QUICKSTART                                   *coc-spring-dashboard-quickstart*

Open the apps tree and start an app from it: >vim
    :CocCommand spring.apps.focus
<
The tree opens in a vertical split on the right. Pick an app and Run it, then
open its dashboard with the actions key of the tree (`<Tab>` by default).
|coc-spring-dashboard-actions| All commands are listed in
|coc-spring-dashboard-commands|.

==============================================================================
LIVE AND STATIC DATA                               *coc-spring-dashboard-live*

Static data comes from the source code: the beans and request mappings that
coc-springboot finds in the workspace. It is there as soon as the project is
indexed.

Live data comes from a running app: its beans, mappings, properties and
memory. An app shows live data once the Spring language server of
coc-springboot is connected to it. The README lists what the app needs.

Icons of an app or of the group of an app in a tree:

  Icon   Meaning ~
  `●`      the app is running, the group shows live data
  `○`      the app is stopped, the group shows static data

The description after a group says which data it shows:

  Description      Meaning ~
  `live, all`        live data, every bean or mapping of the app
  `live, defined`    live data, only what is defined in the source
  `defined`          static data from the source

Refresh the live data of the connected apps by hand: >vim
    :CocCommand spring.dashboard.livedata.refresh
<
The static data rescans the source by itself when you save and when the
index changes.

==============================================================================
VIEWS                                             *coc-spring-dashboard-views*

SPRING APPS is opened with `spring.apps.focus`. The Beans, Mappings,
Properties and Memory views are part of the dashboard of an app and are
reached with the find commands. |coc-spring-dashboard-commands|

==============================================================================
COMMANDS                                       *coc-spring-dashboard-commands*

Every command that `:CocCommand` lists, by what you do. The other commands of
the extension are actions of the trees and are described under
|coc-spring-dashboard-actions|.

Start from SPRING APPS ~
  `spring.apps.focus`                          open the list of apps
  `spring-boot-dashboard.refresh`              look for the apps of the
                                               workspace again
  `spring-boot-dashboard.localapp.run`         run a stopped app
  `spring-boot-dashboard.localapp.debug`       run a stopped app with the
                                               debugger attached
  `spring-boot-dashboard.localapp.settings`    set profiles, port, logging,
                                               JVM options, args and
                                               environment of an app
  `spring-boot-dashboard.localapp.attach`      attach the debugger to a
                                               running app
  `spring-boot-dashboard.localapp.stop`        stop a running app
  `spring-boot-dashboard.localapp.open`        open a running app in the
                                               browser
  `spring-boot-dashboard.localapp.run-multiple`   run several apps at once
  `spring-boot-dashboard.localapp.stop-multiple`  stop several apps at once

The app dashboard ~
  `spring-boot-dashboard.localapp.dashboard`   show the dashboard tab of an
                                               app that has run
  `spring.dashboard.livedata.refresh`          reload the live data of the
                                               connected apps
  `spring.dashboard.showUnderCursor`           show the bean or endpoint
                                               under the cursor in its view

Find ~
  `spring.beans.find`                          find a bean
  `spring.mappings.find`                       find an endpoint
  `spring.properties.find`                     find a property of a running
                                               app

Remote apps ~
  `spring.remoteApp.connect`                   connect a remote app
  `spring.remoteApp.disconnect`                disconnect a remote app

Without a tree line the app commands ask which app to use.

------------------------------------------------------------------------------
APPS                                               *coc-spring-dashboard-apps*

One line per Spring Boot app of the workspace. The icon and description show
the state of the app:

  `○` stopped             not running
  `◐` starting            the JVM is being started
  `◐` waiting for debugger  Debug started the JVM, it waits for the debugger
  `●` running             running; `running :8080` shows the port when live
                        data is connected, also for apps started outside
  `◉` debugging           a debugger is attached

The tooltip shows the main class. `spring-boot-dashboard.refresh` reloads
the list of apps.

Run, Debug and Stop are real. Run and Debug open the launch panel, one
quick pick per app with the action first and the settings below it: >
    Debug bootlab
    > Debug with these settings
      Profiles       dev, local
      Server port    default
      Logging        INFO (debug report: off)
      JVM options    -Xmx512m
      Program args   none
      Environment    DB_URL=...
      Reset to defaults
<
Picking a setting edits it and returns to the panel, the action launches and
`<Esc>` cancels. The settings are remembered per app (kept per workspace);
until then they come from `spring.dashboard.apps`.

  Profiles        a multi-select of the profiles found like upstream does:
                  the `application-<p>` and `bootstrap-<p>` files (properties,
                  yml, yaml) in the source folders of the project and their
                  `config` subfolders. Profiles typed before are offered
                  again, "Type another profile..." adds new ones. Passed as
                  `-Dspring.profiles.active=a,b`.
  Server port     "App default" passes nothing, "Random (0)", or a number;
                  passed as `-Dserver.port=N`. Spring config files are not
                  read for it.
  Logging         the root level (`-Dlogging.level.root`), per package levels
                  such as `com.example=DEBUG` (`-Dlogging.level.<pkg>`) and
                  the `--debug` auto-configuration report.
  JVM options     free text, e.g. `-Xmx512m -Dfoo=bar`.
  Program args    free text.
  Environment     `KEY=VALUE` pairs for the JVM.

`spring.dashboard.launch.prompt` says when the panel opens: `first` (default,
the first time per app, then the remembered settings are used), `always` or
`never`. The "with profile" variants open the panel with the profiles list
already open (also with `never`); a profile given as argument skips it.
"Launch settings..." in the tree actions and
`spring-boot-dashboard.localapp.settings` open the panel without launching.

The app starts as a JVM named "Spring: <app>", with the JMX arguments the
live data needs added for you. The classpath comes from the Java language
server and is passed in an argument file in the storage folder of the
extension. Each app gets a tab at the end of the tab line, its dashboard, with
the working directory set to the project (`:tcd`):
>
    +-----------+-----------+------------+----------+
    | BEANS     | MAPPINGS  | PROPERTIES | MEMORY   |   upper half,
    |           |           |            |          |   4 equal columns
    +-----------+-----------+------------+----------+
    | terminal: the JVM of this run, with the output |   lower half
    +------------------------------------------------+
<
The terminal has the output, colors and input. Running again reuses the tab:
the new terminal replaces the old one, the views stay. The focus stays where
it was, unless `spring.dashboard.launch.focusOutput` is on. "Show app
dashboard" in the tree actions and `spring-boot-dashboard.localapp.dashboard`
switch to the tab, build it again from the terminal of the last run when it
was closed, and restore the layout: a pane you closed comes back and the sizes
are reset. Entering the tab restores a missing pane too. When the app stops
the tab stays, the terminal shows the exit.

A coc tree view lives in one window at a time, so the four views are shown in
the app tab you are in: they move there when you enter it, and the other app
tabs keep the terminal only until they are entered. The views show every live
app, as they do elsewhere. A view with nothing to show has one hint row, for
example "Run <app> to see its properties" or "No beans yet". SPRING APPS stays
its own view on the right of the tab you are in, to start apps from; browsing
the views never opens an app tab. Opening a view with a find command in a
tab that is not an app tab moves it out of the app tab.

Debug starts the JVM suspended, so that breakpoints in the startup code are
hit, and attaches the debugger. Debugging needs nvim-dap (Neovim) or
vimspector (Vim and Neovim, Python 3); without them Debug says so, Run still
works. vimspector opens its own debug tab, needs no .vimspector.json, and
counts as attached until its session is reset. If no debugger attaches
within `spring.dashboard.debug.attachTimeout` seconds the JVM is killed.
Ending the debug session in the debugger only detaches, the app keeps
running.

Defaults per app name, by the name shown in the tree: >json
    "spring.dashboard.apps": {
        "my-app": { "vmArgs": "-Xmx512m", "args": "--debug", "profiles": ["dev"] }
    }
<
Keys: `profiles`, `port`, `logLevel`, `logPackages`, `debugReport`, `vmArgs`,
`args`, `env`.

Stop sends SIGTERM, so that Spring shuts down cleanly, and SIGKILL when the
process is still there after `spring.dashboard.stop.gracePeriod` seconds. It
also stops an app that was started outside the dashboard, by the pid of its
live process. The live process of a dashboard app is paired by pid, other
apps by their main class.

Attach debugger, on an app started with Run, attaches the debugger later;
breakpoints hit from then on. The commands:

  `spring-boot-dashboard.localapp.run`
  `spring-boot-dashboard.localapp.debug`
  `spring-boot-dashboard.localapp.settings`
  `spring-boot-dashboard.localapp.dashboard`
  `spring-boot-dashboard.localapp.attach`
  `spring-boot-dashboard.localapp.stop`
  `spring-boot-dashboard.localapp.run-multiple`
  `spring-boot-dashboard.localapp.stop-multiple`

Without a tree line they ask which app to use; the `-multiple` commands let
you pick several apps, stopped ones for run, running ones for stop. Debug with
several apps is the Debug action of each app.

`spring-boot-dashboard.localapp.open` opens a running app in the browser.
|coc-spring-dashboard-browser|

------------------------------------------------------------------------------
BEANS                                             *coc-spring-dashboard-beans*

One group per app, with the bean names under it. A bean line has:

  `◆` highlighted   the bean is defined in the source, `<CR>` goes there
  `◆` dimmed        the bean has no source in the workspace, the
                  description says `no source`

Commands that work on a bean, the one under the cursor in the tree or one
you pick:

  `spring.dashboard.bean.navigate`           go to the definition
  `spring.dashboard.bean.open`               go to the definition
  `spring.dashboard.bean.showDependencies`   |coc-spring-dashboard-relations|
  `spring.dashboard.bean.showInjectedInto`   |coc-spring-dashboard-relations|
  `spring.dashboard.bean.showHierarchy`      |coc-spring-dashboard-relations|

------------------------------------------------------------------------------
ENDPOINT MAPPINGS                              *coc-spring-dashboard-mappings*

One group per app, with the request mappings under it, shown as the path and
the HTTP method, for example `/owners/{id} [GET]`. A mapping line has:

  `↗` highlighted   the mapping is defined in the source, `<CR>` goes there
  `↗` dimmed        the mapping has no source in the workspace, the
                  description says `no source`

  `spring.dashboard.endpoint.navigate`   go to the definition
  `spring.dashboard.endpoint.open`       open the endpoint in the browser

------------------------------------------------------------------------------
PROPERTIES                                   *coc-spring-dashboard-properties*

One line per running app (`●`), with its property sources (`▤`) under it and
the properties as `name: value` (`·`) under each source.

------------------------------------------------------------------------------
MEMORY                                           *coc-spring-dashboard-memory*

One line per running app, with three lines under it:

  `heap`        used heap in MB, followed by `/ <max> MB`
  `non-heap`    used non-heap memory in MB
  `gc pauses`   total time of the garbage collection pauses in ms,
              followed by `(count <n>)`

Each line shows a sparkline of the latest values, drawn with `▁▂▃▄▅▆▇█`,
and the current value. The values are fetched every
`spring.dashboard.memory-view.fetch-data.delay-in-milliseconds` and the
sparkline keeps `spring.dashboard.memory-view.display-data.max-datapoints`
values. `spring.dashboard.memory.poll` fetches them now.

When an app stops its lines disappear.

==============================================================================
TREE ACTIONS                                    *coc-spring-dashboard-actions*

Press the actions key of the tree (`<Tab>` by default) on a line to get a
menu of what you can do with it:

  Line             Actions ~
  app              Run, Run with profile, Debug, Debug with profile,
                   Launch settings..., Show app dashboard, Stop, Attach debugger
                   (started with Run), Open in browser (running apps only)
  bean             Go to definition (beans with source), Show
                   dependencies, Show injected into, Show hierarchy
  mapping          Go to definition (mappings with source), Open in
                   browser (running apps only)
  bean or mapping  Show all, Show defined
  group

------------------------------------------------------------------------------
SHOW ALL AND SHOW DEFINED                       *coc-spring-dashboard-defined*

A running app has many beans and mappings that come from Spring itself.
Show defined lists only the ones defined in your source, Show all lists
every one. The choice applies to all live groups of the tree and the group
description changes to `live, defined` or `live, all`. Static groups always
show the defined ones.

  `spring.dashboard.bean.showAll`         all live beans
  `spring.dashboard.bean.showDefined`     only the defined beans
  `spring.dashboard.mapping.showAll`      all live mappings
  `spring.dashboard.mapping.showDefined`  only the defined mappings

------------------------------------------------------------------------------
FIND                                               *coc-spring-dashboard-find*

The beans, mappings and properties trees have a filter. These commands open
the tree when needed and start the filter, as if you pressed the filter key
of the tree (`f` by default):

  `spring.beans.find`
  `spring.mappings.find`
  `spring.properties.find`

Type to narrow the lines, `<Esc>` ends the filter.

------------------------------------------------------------------------------
BEAN RELATIONS                                *coc-spring-dashboard-relations*

The relations of a bean open in a |location-list| at the bottom:

- Show dependencies, titled "Dependencies of <bean>": the beans it needs,
  as `name: type` for a bean with source.
- Show injected into, titled "<bean> is injected into": the beans that get
  it injected, as `bean <- field` for a bean with source.
- Show hierarchy, titled "Hierarchy of <bean>": its type, then its
  supertypes indented.

For a bean with source the entries come from the source and `<CR>` on an
entry jumps to it. For a live bean without source they come from the
running app.

==============================================================================
SIGNS IN THE CODE                                 *coc-spring-dashboard-signs*

Java buffers get a sign in the sign column:

  `◆`   a bean definition
  `↗`   a request mapping

Set `spring.dashboard.enableGutter` to `"off"` to hide them.

Show the bean or endpoint under the cursor in its tree: >vim
    :CocCommand spring.dashboard.showUnderCursor
<
It opens the beans or the mappings tree and selects the line. With the
cursor on neither it says "No bean or endpoint under the cursor".

==============================================================================
REMOTE APPS                                      *coc-spring-dashboard-remote*

A remote app is an app on another host that you reach over JMX. List them in
`boot-java.remote-apps` of `coc-settings.json`: >json
    "boot-java.remote-apps": [
        {
            "host": "staging",
            "jmxurl": "service:jmx:rmi:///jndi/rmi://staging:9111/jmxrmi"
        }
    ]
<
  `spring.remoteApp.connect`      pick a remote app and connect it
  `spring.remoteApp.disconnect`   pick a connected remote app and
                                  disconnect it

The pick lists each app as `host (jmxurl)`. A connected remote app shows
live data in the trees like a local running app.

==============================================================================
OPEN IN BROWSER                                 *coc-spring-dashboard-browser*

Open in browser on an app opens its root url, on a mapping it opens the url
of the endpoint. The url follows `spring.dashboard.openUrl`, filled in with
the port and context path of the running app. Both need the app to be
running.

==============================================================================
MESSAGES                                       *coc-spring-dashboard-messages*

"Spring Boot Dashboard needs coc-springboot and coc-java, not active: ..."
    One of the two extensions is not installed or did not start. The
    message names the missing ones. Install them, open a Java file of the
    project and restart coc with `:CocRestart`.

"Spring Boot Dashboard: ..."
    The dashboard failed to start, the error follows. See the output
    channel: `:CocCommand workspace.showOutput Spring Dashboard`.

"No supported debugger found, Debug needs nvim-dap or vimspector"
    Debug and Attach debugger need nvim-dap in Neovim, or vimspector. Install
    one, or use Run.

"no debugger attached within N seconds"
    The debugger did not attach in `spring.dashboard.debug.attachTimeout`
    seconds, the app was stopped. Raise the setting.

"... did not start: ..."
    The JVM could not be started, the reason follows; usually the language
    server has not finished importing the project.

"... is already running", "... is not running"
    Run and Debug need a stopped app, Stop and Attach debugger a running
    one.

"... was not started by the dashboard with Run"
    Attach debugger works on an app that Run started.

"The app of ... is not running"
    Open in browser on a mapping needs the app to run. Start it and
    refresh the live data.

"No bean or endpoint under the cursor"
    `spring.dashboard.showUnderCursor` found no bean or mapping on the
    cursor line. Move to a line with a `◆` or `↗` sign.

"No remote apps to connect, add them to boot-java.remote-apps"
    `boot-java.remote-apps` is empty, or every app in it is already
    connected. |coc-spring-dashboard-remote|

"No Spring Boot app found in the workspace"
    `spring-boot-dashboard.refresh` or an app command found no main class
    with `@SpringBootApplication`. Open a Java file of the project and wait
    for the language server to finish importing it.

"Every app is running already", "No running app"
    Run and Debug need a stopped app, Stop, Open in browser and their
    `-multiple` commands a running one; there is nothing to pick.

"... has no live data yet, wait until it is connected"
    Open in browser needs the live data of the app, which connects a few
    seconds after the start.

"Started ...", "Stopping ...", "Launch settings of ... saved", "Connecting ...",
"Disconnected ..."
    A short notice for a change that is not on screen: the apps view is
    closed (and, for Run, `spring.dashboard.launch.focusOutput` is off).

"No connected app to refresh, run an app or connect a remote one"
    `spring.dashboard.livedata.refresh` has no connected app to refresh.

"No app has a dashboard yet, run one first"
    Show app dashboard needs an app that has run; run one first.

"Spring Boot Dashboard: found ... apps", "... refreshed the live data of ... apps"
    The two refresh commands say what they did when no dashboard view is on
    screen to show it.

"Spring Boot Dashboard: could not ..."
    The apps could not be resolved, the beans and endpoints could not be
    loaded, a live refresh failed or an app did not accept the stop signal.
    The language server may still be starting; the reason follows or is in
    the Spring Dashboard output channel.

"No connected remote app to disconnect"
    `spring.remoteApp.disconnect` has no connected remote app.
